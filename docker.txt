     Docker : 

        if we want to common runtime en where we can run any things without installing any software and depenecey for a particular technology then we should go for docker 

 => the main objective of docker is Contenerization 

=> here we have to learn this topic 
=> dockerFile => where we write the instruction about the software and dependecy whcih is required for particular technology 

=> Docker image=> when we combine app code + software dependency into single unite for excution then it is called 
                   docker image 
=> docker container : when we run docker image then a container is created for the excution of our application ,
                      this container is nothing but docker container (box)
                     when we run docker image multiple times then multiple docker container will created 
                     in the different enmt

        6.EXPOSE

        8.ENTRYPOINT

         ========
          FROM
         ========

             => it is used to specify base image required for our application.
              
                    FROM :jdk11

                    FROM :tomcate8.5
                    
                    FROM :mysql8.5
             
                    FROM :node-19

       =============
        MAINTATNER
       =============
            => it used tell the author of Dockerfile
        MAINTATNER <Shrisht dev>

      =============
        COPY
      =============
      
       =>it is used to copy the files from host machine to container machine.

        COPY <src> <dest>
  
        COPY target/app.jar  /usr/app/tomcat/app.jar
             (source location)  (destination location)

     ====================
         RUN (build)
     ====================
          
       => it is used to execute instruction while creating docker image.

             RUN 'sudo yum install git'
             
             RUN 'sudo yum install maven'
 
             RUN 'git clone <repo>'

      Note:we can run write run instructions in dockerfile and they will be processed from top to bottom

     ================
      CMD/ENTRYPOINT (run)
     ================

     => it is used to excute the instrcutions while creating docker container
                    
            CMD 'java -jar <jar-file>'or ["java","-jar","<jar-file>"]

   Note: if we write the multiple CMD instructions docker will process only last CMD instrcution.

     -------------Dockerfile for Java  Web App(no springboot)-------------

      FROM tomcate-jre:9.5
      MAINTATNER <Shrishtdev>

      EXPOSE 8080
     
      COPY target/app.war /usr/app/tomcate/webapps/

   -----------------------------------------------------------------------

      

     -------------Dockerfile for Sprinboot Application-------------

      FROM openjdk:17
      MAINTATNER <Shrishtdev>

      EXPOSE 8080
     
      COPY target/sbapp.jar /usr/app/
      WORKDIR /usr/app

      ENTRYPOINT ["java","-jar","sbapp.jar"]

   -----------------------------------------------------------------------

      

   ==========Dockerizing Springboot Application=================

     
   1) Install git client in host vm and clone repo

          $ sudo yum install git
          $ git <reppo-url>
  2) Install maven in host vm
        
         $ sudo yum install maven
  3) go to project directory and perform maven build

         $ cd <dir-name>
        $ mvn clean package

 4) Build docker image

      $ docker build -t shrisht/sbapp

 5) Run Docker container using docker image
        
          $ docker run -d -p 8080:8080 shrisht/sbapp
 6) Enable host port in sequrity group

 7)Access application in browser
